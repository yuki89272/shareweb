# 提案簡報敘事結構指南

> 給人看的文件。在你把版型骨架丟給 AI 之前，先用這份想清楚「要說什麼、怎麼排」。

---

## 第一步：確定你的命題

命題是**你觀察到的現象**，不是你打算做的事。

| 正確（命題） | 錯誤（手段） |
|-------------|-------------|
| 每個人都有一段數學記憶 | 我們要讓數學變好玩 |
| 親子客群對數學有共同的挫折經驗 | 用互動展品翻轉數學印象 |

先寫下命題，再問自己：「所以我們打算怎麼辦？」——那個答案才是手段，放在後面的頁才講。

---

## 第二步：排頁序

典型的提案簡報結構：

```
封面
  ↓
命題（為什麼做）     ← 聽眾第一時間要被打動
  ↓
定位（做什麼規格）   ← 客群、場地、時程 = 我們手上的牌
  ↓
結構預覽（怎麼走）   ← 展區/章節的節奏鳥瞰
  ↓
各章節細節 ×N       ← 每章：隔頁 → 概念 → 旗艦展品
  ↓
跨章節/附加內容
  ↓
收束（規模/成果）    ← 大數字、KPI
  ↓
收尾（CTA）
```

### 常見錯誤

1. **Agenda 頁搶戲**：放一頁目錄條列「本簡報涵蓋⋯⋯」，結果劇透了後面所有亮點。直接砍掉，讓每頁自己說話。

2. **定位放在命題前面**：先講行政資訊（場地、時程），聽眾還沒被打動就開始走神。命題永遠放在定位前面。

3. **數據頁放太前面**：「73 個素材精選 33 件」這種數字，要在聽眾看過具體展品之後才有說服力。放在章節細節之後。

---

## 第三步：決定每頁的角色

每一頁只能有一個角色，不要混用：

| 角色 | 功能 | 版型建議 |
|------|------|---------|
| 打動 | 讓聽眾產生共鳴或好奇 | Hero 宣言 |
| 定錨 | 提供事實、設定期待 | 多欄卡片（純文字） |
| 預覽 | 展示結構、給地圖 | 多欄卡片 + icon |
| 展開 | 深入說明具體內容 | 左文右圖、含圖卡片 |
| 喘息 | 大量資訊後的休息 | 呼吸頁 |
| 收束 | 總結、數字說話 | 大數字 / KPI |
| 呼籲 | 引導下一步行動 | 收尾 |

如果一頁同時在「打動」又在「展開」，通常代表它塞太多了——拆成兩頁。

---

## 第四步：交給 AI 之前的 Checklist

- [ ] 我能用一句話說出這份簡報的命題嗎？
- [ ] 頁序是「命題 → 定位 → 預覽 → 細節 → 收束 → CTA」嗎？
- [ ] 每頁我能說出它的角色是什麼嗎？
- [ ] 有沒有哪兩頁在做一樣的事？（合併或砍掉一頁）
- [ ] 大數字/KPI 放在細節之後嗎？

想清楚這些再打開 `slide-system.md` 丟給 AI，效率會高很多。
